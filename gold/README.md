# Phase 1.2 Gold Table Set

This directory holds the manually reviewed gold annotations used to evaluate the
parser against real datasheet pages. The production detector is **not** used to
create any gold data; annotation starts from an independent rule lattice
(`tools/goldset/rules.py`) plus explicit human decisions in `spec.yaml`.

## Contents

| File | Purpose |
| --- | --- |
| `spec.yaml` | Human annotation source: PDF hashes, table/negative decisions, verdict defaults |
| `gold_table_set.jsonl` | Generated records, one JSON object per table or negative |
| `manifest.json` | Generation metadata: PDF SHA256, annotation version, baseline commit, counts |
| `overlays/*.png` | Visual proof for every item (blue table bbox, orange header cells, green body cells, red dashed negatives) |
| `review.html` | Review gallery for all overlays |
| `baseline_report.md` / `.json` | Frozen `1d8c722` baseline evaluation on this set |
| `after_report.md` / `.json` | Five-layer parser evaluation on the same set (`after-5layer-v4`) |
| `comparison.md` | Baseline vs five-layer delta generated by `tools.goldset.compare` |

Regenerate with:

```bash
python -m tools.goldset.annotate
python -m tools.goldset.evaluate --run <lm358-run> --run <ads1299-run> --run <adc12dj5200-run> \
    --label after-5layer-v4 --out gold/after_report.md \
    --json gold/after_report.json --csv gold/after_tables.csv
python -m tools.goldset.compare --before gold/baseline_report.json \
    --after gold/after_report.json --out gold/comparison.md
```

## Annotation rules

- Coordinates are PDF points in the page's post-crop/post-rotate coordinate
  system, identical to `PageGeometry`.
- `component` indexes the rule-lattice component returned by
  `tools.goldset.rules.rule_components` for that page. Components are proposals;
  the spec decides what each one means.
- `header_rows` is the number of header rows at the top of the table.
- `column_roles` must have exactly one entry per logical column. Roles are
  assigned from datasheet headings, not from cell values.
- `column_boundaries` overrides inferred vertical rules when a logical column is
  drawn without an internal rule (for example MIN/TYP/MAX sharing a cell).
- `merges` lists `[row_start, row_end, column_start, column_end]` canopies or
  merged cells that must stay one cell even though rules exist.
- `full_width_rows` marks section/group rows that span every column.
- `cross_page` records `{group, part, relation}` for tables continued on the next
  page. Each page fragment is still its own gold item with its own bbox.
- Negatives carry a `negative_kind` and a bbox. Supported kinds: `prose`, `toc`,
  `pin_diagram`, `chart_annotations`, `revision_history`, `timing_diagram`,
  `legal_notice`, `bit_field_diagram`.

### Verdict semantics

- `human_verdict: accepted` — annotator checked the overlay: table bbox, cell
  boxes, header depth, merges and semantic roles match the datasheet.
- `pending` — not reviewed; excluded from evaluation.
- `rejected` — reviewed and found wrong; excluded from evaluation.

Current state: all items are `accepted` by the annotator; independent reviewer
sign-off is still `pending` in `manifest.json`.

## Evaluation protocol

`tools/goldset/evaluate.py` scores a parser run against this set.

- Predictions are matched to gold tables on the same page by IoU, one-to-one,
  greedy by descending IoU; a match requires IoU >= 0.5.
- **Region scope**: only predictions that overlap an annotated region count as
  false positives. Overlap is intersection over prediction area >= 0.25.
  Predictions on gold pages but completely outside every annotated region are
  reported separately as `out_of_scope_predictions` and are not scored, because
  gold pages are page-sampled rather than exhaustively annotated for every
  figure and unlabelled graphic.
- A prediction that overlaps a negative bbox and matches no gold table is a
  negative false positive, reported by `negative_kind`.
- Structure metrics are computed only for matched predictions: row/column count
  agreement, cell-text multiset F1, header label agreement, coarse column-role
  agreement (the baseline vocabulary is `min/typ/max/unit/condition/symbol/
  value/unknown`; finer gold roles map into it), and table-type exact match.
- Single-row gold tables are counted and reported explicitly. They are never
  excluded from recall, and a parser that drops them is penalized by recall.
- `reconstructed` is a parser status, not evidence of correctness; status
  distributions are reported alongside structure metrics.
